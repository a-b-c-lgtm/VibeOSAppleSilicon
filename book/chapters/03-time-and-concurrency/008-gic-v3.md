## What the GIC is, and why we need v3

The Generic Interrupt Controller (GIC) is ARM's standard interrupt
plumbing. On every multiprocessor AArch64 SoC the GIC is
responsible for:

- **Routing** — taking a peripheral's IRQ wire and presenting it
  to one (or many) CPU(s) as an exception.
- **Prioritising** — when several IRQs are pending, picking the
  highest-priority one to deliver.
- **Acknowledging** — providing each CPU with an atomic
  read-and-clear primitive so that the kernel knows *which* IRQ
  fired without races.
- **End-of-interrupt** — letting the kernel tell the GIC "I'm done
  with this one; allow lower-priority IRQs through again".

Three GIC architecture revisions are commonly seen:

| Version | First seen | Defining feature                                  |
|---------|------------|---------------------------------------------------|
| GICv2   | Cortex-A15 | MMIO CPU interface; up to 8 CPUs                 |
| GICv3   | Cortex-A53 | System-register CPU interface; LPIs; affinity     |
| GICv4   | (variants) | Direct VM injection (vLPI)                        |

We standardise on v3 because:

1. The QEMU virt machine exposes a v3 to guests when invoked with
   `gic-version=3`, and HVF emulates exactly that to its guests.
2. The v3 CPU interface is reached through `mrs`/`msr` to
   `ICC_*_EL1` system registers, not MMIO. That removes one whole
   class of MMIO-writeback hazards (chapter 3) and matches the
   Cortex-A72 / Apple-silicon programming model.
3. Affinity routing (the GICv3-only mechanism for delivering an
   SPI to a specific CPU using its MPIDR) is what we will rely on
   when threads land in chapter 10.

## The three pieces

GIC v3 is split into three logical blocks that we touch
separately:

| Block               | Where                                    | What it owns               |
|---------------------|------------------------------------------|----------------------------|
| Distributor (GICD)  | MMIO at `0x0800_0000`                    | SPIs (IDs 32–1019)         |
| Redistributor (GICR)| MMIO at `0x080A_0000` for CPU 0          | SGIs and PPIs (IDs 0–31)   |
| CPU interface       | system registers `ICC_*_EL1`             | acknowledge / EOI for *this* CPU |

The redistributor has two register pages 64 KiB apart:

- `GICR_RD_base` at `0x080A_0000` — high-level control (`GICR_CTLR`,
  `GICR_WAKER`, …).
- `GICR_SGI_base` at `0x080A_0000 + 0x10000` = `0x080B_0000` — per-
  CPU SGI/PPI enable, priority, and group registers.

If you look at `gic.c` you will see a pair of macros that reflect
those two bases exactly:

```c
#define GICR_BASE        0x080A0000UL      /* CPU 0 */
#define GICR_SGI_BASE    (GICR_BASE + 0x10000)
```

A multi-CPU build would extend `GICR_BASE` with an array indexed
by CPU number; chapter 10 does that when it boots the secondary
cores.

## Interrupt classes

The GIC uses a 32-bit interrupt ID (the *INTID*) for everything,
but the low end of the ID space is partitioned by class:

| Class  | INTID range | Source                                                | Lives in        |
|--------|-------------|-------------------------------------------------------|-----------------|
| SGI    | 0–15        | Software-Generated (CPU-to-CPU IPI)                   | Redistributor   |
| PPI    | 16–31       | Private Peripheral (per-CPU; e.g. timer)              | Redistributor   |
| SPI    | 32–1019     | Shared Peripheral (most platform devices)             | Distributor     |
| LPI    | 8192+       | Locality-specific Peripheral (MSI; rare under QEMU)   | ITS (not used)  |

The reason this split *matters at the driver level* is that the
"enable this IRQ" register lives in different places for SGI/PPI
versus SPI:

- SGIs and PPIs are enabled via `GICR_ISENABLER0` (a single 32-bit
  register holding all 32 PPI/SGI enable bits, in the
  redistributor's SGI page).
- SPIs are enabled via `GICD_ISENABLER<n>` in the distributor,
  with one bit per ID in a 32-IDs-per-register array.

Compare the two halves of `gic_enable_irq`:

```c
void gic_enable_irq(uint32_t intid)
{
    if (intid < 32) {
        /* SGI or PPI — lives in the redistributor. */
        mmio_write32(GICR_ISENABLER0, 1u << intid);
    } else {
        /* SPI — lives in the distributor. */
        uint32_t reg = intid / 32;
        uint32_t bit = intid % 32;
        mmio_write32(GICD_ISENABLER(reg), 1u << bit);
    }
}
```

## The bring-up sequence

`gic_init` walks through three phases in order:

1. **Quiesce the distributor.** Write `0` to `GICD_CTLR` so that
   no rule changes mid-flight cause spurious deliveries.

2. **Wake the redistributor for this CPU.** After reset the
   redistributor is in a low-power state with
   `GICR_WAKER.ProcessorSleep = 1`. Clear that bit and poll
   `GICR_WAKER.ChildrenAsleep` until it reads zero:

   ```c
   uint32_t waker = mmio_read32(GICR_WAKER);
   waker &= ~GICR_WAKER_PROCESSOR_SLEEP;
   mmio_write32(GICR_WAKER, waker);
   while (mmio_read32(GICR_WAKER) & GICR_WAKER_CHILDREN_ASLEEP) { }
   ```

   Skipping this poll is the single most common GIC bring-up bug:
   the writes to `GICR_ISENABLER0` succeed but never deliver,
   because the redistributor is still asleep.

3. **Configure and enable the CPU interface.** Four system-
   register writes:

   ```c
   icc_sre_el1_write(icc_sre_el1_read() | 1ULL);   // SRE = 1
   icc_pmr_el1_write(0xFFULL);                      // priority mask = let everything through
   icc_bpr1_el1_write(0ULL);                        // no preemption grouping
   icc_igrpen1_el1_write(1ULL);                     // group-1 enabled
   ```

   - `ICC_SRE_EL1.SRE` selects "system registers" over the legacy
     memory-mapped CPU interface. If a hypervisor leaves
     `ICC_SRE_EL2.SRE` clear, this write traps to EL2 with EC=0
     (chapter 5) — that is the canonical "you are running under
     a host that did not enable v3 system registers" symptom.
   - `ICC_PMR_EL1` is the *priority mask*. The CPU interface only
     delivers IRQs with priority strictly less than this value.
     `0xFF` (the lowest priority) means "deliver everything";
     setting it to `0x80` means "block anything with priority
     `≥ 0x80`". We never use it for masking yet; the
     scheduler in chapter 11 will use it to implement IRQ
     priority levels.
   - `ICC_BPR1_EL1` is the *binary point register*: it controls
     how many priority bits participate in pre-emption grouping.
     Setting it to 0 means "every priority preempts every lower
     priority" — the most permissive setting. We never need
     anything else.
   - `ICC_IGRPEN1_EL1.Enable` finally turns on group-1 NS IRQ
     delivery.

4. **Re-enable the distributor.** Set both `ARE_NS` (affinity
   routing for non-secure SPIs) and `EnableGrp1NS`:

   ```c
   mmio_write32(GICD_CTLR, GICD_CTLR_ARE_NS | GICD_CTLR_ENABLE_G1NS);
   ```

   `ARE_NS` is required by GICv3 — without it, the distributor
   keeps using GICv2-style targeting and PPIs do not route
   through the redistributor at all. This is the subtle one: omit
   `ARE_NS` and the timer IRQ never fires.

## The acknowledge / EOI cycle

When the CPU takes an IRQ exception (slot 5 in our vector table),
the handler runs. To find out *which* IRQ fired and to allow more
to come in, the handler executes:

```c
uint32_t intid = gic_acknowledge_irq();   // mrs ICC_IAR1_EL1
... handle it ...
gic_end_of_irq(intid);                    // msr ICC_EOIR1_EL1
```

The acknowledge step atomically reads the highest-priority pending
INTID and changes its state from "pending" to "active". The
end-of-interrupt step changes the state from "active" back to
"inactive" and (with the default `EOImode` of 0) also drops the
*running priority* on the CPU interface so further IRQs of equal
or lower priority can be taken.

Two failure modes are worth mentioning:

- **Forgetting to EOI** leaves the priority elevated; subsequent
  IRQs at the same priority (e.g. the very next timer tick) are
  blocked at the CPU interface. The first symptom is "I see one
  heartbeat, then nothing".
- **EOI'ing a different INTID than you ack'd** is a programming
  error. The architecture *does not* check, but the GIC behaves
  unpredictably afterwards. Always pair them in the same
  variable.

The "spurious INTID" (1023) is what `ICC_IAR1_EL1` returns when
no real IRQ is pending — for example because a higher-priority
handler already ack'd ours. The dispatcher checks for it and
returns immediately without EOI'ing:

```c
uint32_t intid = gic_acknowledge_irq();
if (intid == 1023) return;
```

## The vector-table tie-in

`vectors.S` slot 5 (offset `0x280`, "IRQ from current EL using
SP_ELx") used to branch to `panic_entry`. This chapter redirects
it to a new `irq_entry`:

```asm
    .balign 0x80
    b       irq_entry           /* slot 5: IRQ from EL1h */
```

`irq_entry` runs the same `save_context` as `panic_entry`, calls
the C dispatcher with the frame pointer in `x0`, restores the
frame, and returns via `eret`:

```asm
.global irq_entry
irq_entry:
    save_context
    mov     x0, sp
    bl      irq_dispatch
    restore_context
    eret
```

The new `restore_context` macro is the symmetric inverse of
`save_context` (chapter 5): pop ELR/SPSR back into the system
registers, ldp every GP register, then `add sp, sp, #272`. The
order matters — we must write `ELR_EL1` and `SPSR_EL1` *before*
restoring x0/x1, because the inline pop uses x0/x1 as scratch.

`irq_dispatch` itself is in `kernel/core/irq.c` and is one switch
statement:

```c
void irq_dispatch(struct exception_frame *frame)
{
    (void)frame;
    uint32_t intid = gic_acknowledge_irq();
    if (intid == 1023) return;

    switch (intid) {
    case TIMER_CNTV_INTID:
        timer_rearm();
        timer_tick();
        break;
    default:
        serial_puts("[irq] unexpected intid ");
        serial_puthex(intid);
        serial_puts("\n");
        break;
    }

    gic_end_of_irq(intid);
}
```

Chapter 21 (virtio-mmio) replaces the switch with a registered-
handler array. Until then, every new IRQ source adds one `case`.

## What chapter 8 adds

The GIC is now configured but no peripheral is asking for any
interrupts. Chapter 8 lights up the ARM generic timer at PPI
INTID 27 (the "virtual" CNTV timer, which is the one accessible
to guests under HVF), enables it through `gic_enable_irq(27)`,
unmasks IRQs in PSTATE, and gives us the heartbeat we will use
for the rest of the book.
